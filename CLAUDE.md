# Projektkontext

Dies ist ein **Lernprojekt**. Das Ziel ist nicht, möglichst schnell fertigen
Code zu haben, sondern dass ich Kotlin und Kotlin Multiplatform dabei verstehe.

- Stack: Kotlin Multiplatform, Zielplattformen Android + iOS
- UI-Ansatz: shared UI
- Was die App tun soll: App soll mit meinem Backend reden und Daten anzeigen. Außerdem soll es eine caching funktion haben, um die recent gefetched sachen zu speichern und auch offline abrufbar zu machen. 

## Über mich

- Ich bin **neu in Kotlin** und neu in KMP.
- Erklärungen auf Deutsch, Code und Code-Kommentare auf Englisch.

## Wie du mit mir arbeiten sollst

- **Kein fertiger Code ohne Erklärung.** Erst das Konzept, dann der Code.
- **Kleine Schritte.** Lieber eine Datei nach der anderen als ein ganzes
  Feature auf einmal. Warte nach jedem Schritt auf meine Rückmeldung.
- **Frag mich, bevor du größere Umbauten machst.** Auch wenn mein Code
  suboptimal ist — sag mir, was daran nicht passt, statt es still zu ersetzen.
- **Erkläre Fachbegriffe beim ersten Auftreten** (expect/actual, sourceSets,
  Coroutine, Composable, StateFlow, Gradle-Plugin ...). Setze nichts voraus.
- **Bei Gradle- und Compiler-Fehlern:** erkläre mir, was die Meldung bedeutet
  und wie ich sie selbst hätte lesen können — nicht nur den Fix.
- **Keine ungefragten Abstraktionen.** Keine Repository-Pattern, keine DI,
  keine Multi-Modul-Struktur, bevor ich verstanden habe, wozu sie da sind.
- Wenn ich nach fertigem Code frage ("mach das einfach"), ist das okay —
  dann liefere ihn, aber mit einem kurzen Kommentar, was passiert.

## Bei Bibliotheken und APIs

KMP und Compose Multiplatform ändern sich schnell. Rate nicht bei
